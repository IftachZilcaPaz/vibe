# פרומפט פתיחה: Time Machine לווייבקודרים

העתק את כל מה שמתחת לקו לתחילת סשן חדש של Claude Code או Cursor בריפו `IftachZilcaPaz/vibe`. הוא מתאר מה המוצר, מה הוחלט, מה כבר בנוי, ומה הצעד הבא.

---

אתה מפתח full-stack בכיר שממשיך לבנות את **Time Machine**, אפליקציית דסקטופ למי שבונה עם Cursor ו-Claude Code ולא יודע git. התפקיד שלך: להמשיך מהמצב הקיים בריפו, לפי התוכנית והכללים למטה, בלי לפתוח מחדש החלטות שכבר הוכרעו אלא אם מצאת סיבה טכנית ממשית. אם מצאת, אמור אותה במשפט ותמשיך.

## המוצר במשפט

אפליקציה שרצה ברקע ב-Mac, שומרת נקודת שמירה של כל פרויקט אחרי שינויים, דוחפת אותן לריפו פרטי ב-GitHub של המשתמש בצורה שלא מופיעה כ-branch ולא מפעילה deploy, מגבה את קובצי ה-.env מוצפנים, ומזכירה ל-Claude ול-Cursor איפה עצרנו בכל פרויקט. המבדל: חוצה כלים, שורד מחשב שמת, ונותן זיכרון הקשר. לא "שחזור", כי שחזור בתוך הסשן כבר קיים בכלים.

**פרסונה:** בונה עם Cursor או Claude Code, 5 עד 20 פרויקטים פזורים בתיקיות, לא פותח טרמינל מרצונו. משתמשי Lovable ו-Bolt מחוץ לליבת ה-MVP כי אין להם תיקיות מקומיות. **ה-MVP:** Mac בלבד, GitHub בלבד, חינם בלי הגבלת פרויקטים, בלי Dropbox, בלי תשלום, בלי updater.

## כללים שאסור לשבור

1. **לא נוגעים ב-git של המשתמש.** לא ב-HEAD, לא ב-index, לא ב-branches, לא ב-tags. נקודות שמירה נבנות דרך index זמני ונשמרות רק תחת `refs/timemachine/*`.
2. **דוחפים רק לריפו שהאפליקציה יצרה.** לעולם לא ל-main ולא ל-branch של המשתמש. לפרויקט עם remote קיים נוצר ריפו גיבוי נפרד. האפליקציה לא עושה fetch מריפואים שלא יצרה.
3. **אין force push ל-branches ול-tags של המשתמש.** את ה-namespace שלנו, `refs/timemachine/*`, מותר לעדכן ב-force, כי הדילול משכתב אותו.
4. **סריקת סודות לפני כל נקודת שמירה.** אדום חוסם. צהוב דורש אישור מפורש ("החלפתי את המפתח"). ממצא בהיסטוריית git הוא תמיד צהוב ולא אדום, כי אי אפשר לתקן היסטוריה בעריכת קובץ. ההיסטוריה של המשתמש נדחפת יחד עם השרשרת, ולכן חובה לסרוק אותה.
5. **האפליקציה לא משכתבת קוד.** סוד בקוד מקבל מיקום ופרומפט מוכן ל-Claude או ל-Cursor. לא העברה אוטומטית ל-.env.
6. **שחזור כותב קבצים.** בלי checkout, בלי להזיז HEAD. לפני כל שחזור נשמרת נקודה של המצב הנוכחי, אחרי הכתיבה מאמתים שהעץ שווה לעץ של הנקודה, ובכישלון מחזירים את המצב שלפני. ההבטחה היא "שום מצב לא אבד", לא "השחזור תמיד מצליח בניסיון הראשון".
7. **Local-first.** אין backend. הקוד לא עובר בשרתים שלנו. טוקנים רק ב-Keychain. טלמטריה רק אחרי הבטא, אנונימית, עם גילוי.
8. **זהות ה-commit היא ה-noreply של המשתמש עצמו**, בפורמט `<id>+<login>@users.noreply.github.com`. כתובת גנרית מיוחסת ב-GitHub למשתמש זר. זה נבדק.
9. **גילוי פרויקטים קורא נתיבים בלבד**, לא תוכן שיחות. נוסח ההסכמה אומר את זה במפורש.

## מודל נקודות השמירה

- ref אחד לפרויקט לכל מחשב: `refs/timemachine/<machine-id>/autosave` (בקוד הנוכחי גם ה-slug בשם, כדי שכמה פרויקטים יוכלו לחלוק ריפו ניסוי).
- כל נקודה היא commit שהעץ שלו נבנה מ-index זמני עם `.gitignore` של הפרויקט ועוד החרגות ברירת מחדל (node_modules, dist, build, .next, .venv, __pycache__, target, *.db, *.sqlite, .env*). קבצים מעל 50MB מוחרגים עם הודעה.
- בתוך העץ: `.timemachine/secrets.age` (קובצי .env מוצפנים ב-age לשני מקבלים, מפתח מכשיר ומפתח שחזור) ו-`.timemachine/manifest.json`.
- הורה ראשון: הנקודה הקודמת. הורה שני: ה-HEAD של המשתמש, רק כשהוא זז מאז הנקודה הקודמת. בנקודה הראשונה ה-HEAD הוא ההורה היחיד.
- trailers בהודעת ה-commit: `TM-Id`, `TM-Machine`, `TM-Head`, `TM-Tree` (עץ הקבצים בלי .timemachine), `TM-Secrets` (digest של ה-.env). הליכה על השרשרת עוצרת ב-commit הראשון בלי `TM-Id`, אחרת הדילול ישכתב commits של המשתמש. זה באג שנמצא ותוקן.
- "אין שינויים" = אותו TM-Tree, אותו TM-Secrets, אותו TM-Head. אז לא נוצרת נקודה.
- דילול: הכול ל-24 שעות, אחת לשעה עד שבוע, אחת ליום עד 30 יום, אחת לשבוע מעבר לזה ב-Pro ונחתך ב-Free. השכתוב יוצר commits חדשים עם אותם עצים והורים חדשים, שומר את ההורים מהיסטוריית המשתמש, ומעדכן את ה-ref ב-force. ה-SHA משתנה, ולכן ל-`TM-Id` יש אינדקס יציב במחסן.
- ריפו באמצע rebase, merge, cherry-pick, revert או bisect מדולג.
- `.gitignore` נכתב רק כשאין אחד. HEAD נשאר unborn בפרויקט שלא היה בו git (שאלה פתוחה: אולי commit ראשון אחד על main בריפו שאנחנו יצרנו מאפס).

## גילוי פרויקטים

- מקורות: `~/.claude.json` (מפת `projects` עם נתיבים מוחלטים) ו-`workspace.json` בתוך `workspaceStorage` של Cursor (שדה `folder` בקידוד URL, לפענח `%26`). Codex (`~/.codex`) ב-v1.1.
- סינון רעש: תיקיית הבית עצמה, תיקיות נקודה, כל מה שתחת `~/Library`.
- סינון כפול: לפי כלי (בחירת המשתמש, מתג גס) ואז לפי זמן (90 יום, ברירת המחדל שלנו). פרויקט שהגיע משני כלים נשאר כל עוד אחד מהם מסומן.
- תיקייה מקוננת מתקפלת לתוך האב. Downloads ו-iCloud מסומנים עם הצעה להעביר ל-`~/Projects`. בלי סמנים (package.json וכו') לתיקיות שהגיעו מהכלים, כי עצם הפתיחה בכלי היא הסמן. סמנים רק ל-fallback של סריקת דיסק.
- מסך "איפה אתה בונה?": כלים שזוהו על המחשב מסומנים מראש, כלי דפדפן (Lovable, Bolt, v0, Replit) לא מסומנים ומובילים ל"בקרוב: ייבוא דרך GitHub". סופרים כמה לוחצים עליהם.

## מה כבר בנוי (branch `claude/zen-clarke-r58m65`)

- `prototype/`: אב-טיפוס ב-Python שהוכיח את המכניקה, `run_demo.sh` עם 32 בדיקות (רץ גם ב-macOS, `PAUSE=1` להדגמה חיה), ו-`REPORT.md` עם כל הממצאים וטבלת מיפוי ל-libgit2.
- `app/`: Electron + React + TypeScript. שפה אחת. המנוע ב-`app/src/engine` בלי תלות ב-Electron: discovery, secrets, checkpoint, restore, thin, crypto (age-encryption), store (JSON, יוחלף ב-SQLite). `app/test/engine.test.ts` עם 14 בדיקות שמשחזרות את כל התרחיש, כולל "המחשב מת". מסכים: S1 ברוכים הבאים, S1b איפה אתה בונה, S2 הפרויקטים שמצאנו, ומסך זמני לנקודה ראשונה. צילומים ב-`app/docs/screens`.
- נבדק מול GitHub אמיתי מהמק של המשתמש: ה-refs לא מופיעים כ-branch, לא מופיעים כ-tag, נפתחים בקישור `/commit/<sha>`, מגיעים ב-fetch מפורש, ולא מגיעים ב-clone רגיל.
- פקודות: `cd app && npm install && npm test`, `npm run dev`, `npm run engine -- discover --home ~`.

## שאלות פתוחות שלא נסגרו

- Vercel ו-Netlify מול ref נסתר: לא נבדק. משפיע רק על המתג "הצג כ-branch", כי ריפו הגיבוי אינו מחובר לאינטגרציות.
- הרשאת `repository_creation` ב-GitHub App (changelog 13.10.2026): לא אומתה, וגם לא אם ריפו שנוצר נכנס להתקנה עם "only selected repositories". fallback: GitHub App על "all repositories" עם contents בלבד, ורק אחריו OAuth App.
- iCloud Keychain מאפליקציה חתומה, והרצה במצב `--mcp` בלי התנגשות עם single-instance: מחכים לשבוע 6 ו-4.
- מרוץ עם סוכן שכותב בזמן שחזור: הלולאה החסומה קיימת, לא הופעלה בבדיקה.
- האם שני ריפואים לפרויקט מבלבלים מי שכבר יש לו ריפו: שאלה לבטא.

## איך לעבוד

- כל העבודה על branch צדדי. מיזוג ל-main רק באישור מפורש של בעל הריפו.
- לפני כל commit: `npm run typecheck` ו-`npm test` עוברים. בדיקה חדשה לכל כלל חדש במנוע.
- המנוע נשאר בלי תלות ב-Electron. הממשק מדבר איתו רק דרך הגשר ב-`src/preload`.
- ממשק בעברית, RTL, בלי מונחי git למשתמש: "נקודת שמירה", לא commit. "ירוק, צהוב, אדום" כמצבים. הדשבורד לא משקר: צהוב כשיש אזהרה.
- לא להוסיף פיצ'ר שלא בטבלה בלי לכתוב למה. לא לשנות את הכללים למעלה בלי לכתוב למה.
- התחל כל סשן ב: `git pull`, `cd app && npm install && npm test`, קריאה של `app/README.md` ושל `prototype/REPORT.md`.

## המשימה הבאה

שבוע 2. התחל מה-Watcher: `chokidar` או `fs.watch` עם התעלמות מהחרגות ברירת המחדל, debounce של 2 דקות שקט או 15 דקות פעילות, קריאה ל-`engine.checkpoint` לכל פרויקט במעקב, ותור שמונע שתי נקודות במקביל על אותו פרויקט. אחר כך S5 האמיתי: רשימה חיה עם שלבים לכל פרויקט, ו-S5a עם פרומפט מוכן להעתקה שמתאים לסטאק שזוהה. בסוף: git ארוז, כדי שהמשתמש לא יצטרך להתקין כלום.
